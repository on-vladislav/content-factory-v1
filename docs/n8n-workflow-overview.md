# n8n в проекте

n8n связывает пользовательские интерфейсы и производственный контур Content Factory.

Рабочие workflow не публикуются в открытом репозитории: они привязаны к конкретным базам Notion, Telegram-чатам и окружению. Для итогового проекта используются скриншоты без секретов и описание ответственности каждого потока.

## Ключевые потоки

1. **Telegram → Notion** — принимает идею или материал и создаёт карточку в «Радаре контента».
2. **Notion → Codex / Content Factory** — передаёт структурированный контекст: аудиторию, проблему, главную мысль, источник, CTA и ограничения.
3. **Codex / Content Factory → Notion** — возвращает черновик, контент-план, ревизию и технический статус.
4. **Комментарий или ручная правка → ревизия** — запускает отдельный цикл изменения, не смешивая AI-версию и ручную.
5. **Утверждение → планирование → publisher** — разделяет согласование текста и разрешение на публикацию.
6. **Publisher → Notion** — записывает дату, статус и подтверждённую ссылку после отправки.

## Что показать на скриншотах

- общий граф workflow;
- узлы Telegram и Notion;
- передачу задания в Content Factory;
- возврат результата в Notion;
- ветку ручной правки и `MANUAL_LOCK`;
- публикационный поток и возврат ссылки.

Перед публикацией скриншоты нужно проверить на отсутствие токенов, ID секретов, webhook URL и внутренних адресов.
