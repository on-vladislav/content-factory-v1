# Публикация в Telegram: production-контур и JSON-экспорт

Production-сценарий проекта публикует Telegram-версию через `Content Factory API → PostgreSQL → n8n Telegram publisher`.

Дневной JSON-пакет остаётся каноническим экспортом комплекта публикаций для будущего SMMBox и других площадок. Локальные скрипты этого каталога не участвуют в обычной автоматической публикации.

```text
источник → дневной JSON → проверка Владом → approved → scheduled
→ API/PostgreSQL → Telegram publisher → published → Notion и журнал
```

Создание или утверждение JSON само по себе ничего не отправляет.

## Формат пакета

Сценарий `publish_from_json.py` принимает два формата:

- старый `agency-content/v2`: текст берётся из `platforms.telegram.content`, результат записывается в `publication.telegram`;
- новый `agency-content/day-v1`: текст берётся из `publications.telegram.content`, результат записывается в `publications.telegram`.

Обложка в обоих форматах берётся из `assets.cover.path`.

Редакционные ограничения:

- Telegram с обложкой: комфортно `900–1000`, максимум `1024` видимых символа;
- MAX: комфортно `500–800`, максимум `1000` символов;
- HTML-теги Telegram не входят в подсчёт видимых символов;
- текст Telegram должен помещаться в подпись к обложке; вариант «обложка отдельным сообщением, текст ответом» не используется как штатный формат.

## Предварительная проверка

Проверка не требует токена и не обращается к Telegram:

```text
python automation/telegram-publisher/publish_from_json.py reports/PACKAGE.json --root .
```

Режим показывает длину Telegram- и MAX-версий, наличие обложки и редакционные предупреждения.

## Реальная публикация

Для отправки нужны переменные окружения:

- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TELEGRAM_CHAT_ID` — публичное имя канала вида `@channel` или его числовой идентификатор.

Токен нельзя сохранять в JSON, Markdown, реестре, сценарии или журнале.

Ручной запуск `publish_from_json.py --publish` не является штатным production-путём. Он оставлен для локальной проверки, аварийного восстановления и будущего экспорта в SMMBox.

Штатная публикация запускается через статус и дату в Notion:

```text
Notion: Следующий шаг = «опубликовать» + дата
→ n8n → Content Factory API → Telegram publisher
```

Допускаются только пакеты со статусом `approved` или `scheduled`. Для `scheduled` время `publication.telegram.scheduled_at` должно уже наступить. Без отдельного запуска сценарий не ждёт указанное время и ничего не отправляет.

Перед обращением к Telegram сценарий записывает технический статус `sending`. После успешной отправки он фиксирует:

- `status: published`;
- `publication.telegram.status: published`;
- `published_at`;
- `published_url`;
- идентификаторы отправленных сообщений.

При неоднозначной ошибке устанавливается `ambiguous`, а повторная отправка блокируется до ручной проверки канала.

## Подключение бота

1. Использовать существующего бота или создать нового через `@BotFather`.
2. Добавить бота администратором сначала в тестовый канал.
3. Выдать только право публикации сообщений.
4. Сохранить токен вне проекта в переменной окружения.
5. Проверить пакет без отправки.
6. Выполнить тестовую публикацию в тестовый канал.
7. После проверки отдельно подключить основной канал.

## Исторические сценарии

Файлы `publish_scheduled.py` и `n8n-workflow.json` относятся к прежнему эксперименту с Markdown и n8n. `publish_from_json.py` сохраняется как локальный резервный инструмент и валидатор JSON, но не должен включаться параллельно с production publisher.
